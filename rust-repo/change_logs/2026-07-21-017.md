# Migration Log 2026-07-21-017

Status: Completed

Baseline: `110bfa47aabc713ef1cdf`

## Rust-backed Python service lifecycle parity

### Upstream

- `6aa80e25` makes Store REST startup and serving terminate cleanly on SIGINT
  or SIGTERM.
- `33016145` rejects missing, empty, and whitespace-only bootstrap metadata
  keys and normalizes valid keys before lookup or mutation.

### Rust migration

- The pre-change Rust wheel shipped only the extension module and did not
  inherit the Python service modules from `mooncake-wheel`.
- Add Rust-wheel-owned `mc_store_rest_server` and
  `mooncake_http_metadata_server` console scripts.
- Drive startup retry and the HTTP lifetime from one asyncio shutdown event.
  SIGINT and SIGTERM set that event, retry waits are interruptible, and the
  Rust client is closed exactly once from a `finally` block.
- Reject missing, empty, and whitespace-only metadata keys with HTTP 400 and
  strip valid keys before dispatch.
- Load the native extension lazily so pure Python service modules can be
  imported before the platform extension is first needed.
- Exclude Python bytecode caches from the built wheel.

### Verification

- `python3 -m unittest discover -s tests -v`: 6 passed.
- A no-native-link audit wheel contains both service modules, both console
  scripts, and no `__pycache__` or `.pyc` files; the same six tests pass with
  that wheel first on `PYTHONPATH`.
- The normal release wheel reached native linking, where this host lacks the
  prebuilt `libtransfer_engine` and `libtent_shared` shared libraries.
- `cargo check -p mooncake-store-py --all-targets` verifies the Rust binding
  targets with the configured features.
