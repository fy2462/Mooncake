# Migration Log 2026-07-21-010

Status: Completed

## Scope

Migrate upstream `b996ac4b` opt-in remote MEMORY replica scoring using
client-owned, idiomatic Rust state.

## Rust design

- Add public `ReplicaSelectionPolicy`, `ReplicaScorer`, and
  `builtin_remote_replica_score` APIs.
- Store one immutable policy value on each `MooncakeClient`.
- Accept injected scorers as thread-safe `Arc` closures.
- Allow policy replacement through `&mut MooncakeClient`; no process-global
  mutable scorer or lock is introduced.
- Extract the selection algorithm into a pure function shared by all client
  read paths through the existing `select_best_replica` adapter.

## Behavior parity

- Scoring is disabled by default and enabled by
  `MC_STORE_REPLICA_SCORING=1`, or explicitly by a built-in/custom policy.
- Built-in scoring orders `rdma < tcp < unknown` and assigns non-memory
  replicas the compatibility score 100.
- Only COMPLETE remote MEMORY replicas are scored.
- Strictly-lower comparison preserves master order for ties and falls back to
  the historical first remote MEMORY if all scores are unusable, such as NaN.
- Local MEMORY/NoF short-circuit behavior, remote NoF order, LocalDisk/Disk
  fallback, and no-candidate behavior are unchanged.

## Read-path coverage

- Single reads, ordinary batch reads, and range reads already delegate to the
  central `MooncakeClient::select_best_replica` adapter and therefore share the
  policy.
- Explicit same-node batch preference remains an earlier local-only override.
