# Migration Log 2026-07-21-016

Status: Completed

Baseline: `110bfa47aabc713ef1cdf`

## Architecture boundary

- Treat Transfer Engine as an upstream dependency and minimize changes to it.
- Reuse existing TE/TENT behavior through FFI. If the current C ABI cannot
  expose a required capability, add only the thinnest versioned entry point to
  the existing TENT C API.
- Keep validation, compatibility routing, ownership and lifetime handling, and
  ergonomic Rust/Python APIs in the `rust-repo` FFI adapter layers.
- Do not introduce `unsafe` into `mooncake-store-client/src/client/**`.

## Versioned TENT intent, QoS, cancellation, and metrics API

### Upstream

- Request controls from `4d1116ad`, `ab89448f`, `88be9e92`, `9cd1277a`,
  `cc9e5250`, `6a4627f5`, `e68b30d0`, and `6d92ac1c` are reachable through
  priority, policy, absolute deadline, intent, transport, and generic TENT
  configuration overrides.
- Best-effort cancellation from `2b5a1f92` is bound through the existing
  `tent_cancel_task` C API.
- Metrics visibility covers the causal/QoS metrics work in `6aa0ae65` and
  `cdba6f8a`, plus the real HTTP bind status fixed by `8009138b`.
- QoS contract configuration from `6223076c` remains native-owned and can be
  selected through the existing TENT configuration surface.

### Rust migration

- Preserve the layout and behavior of both legacy `transfer_request_t` and
  `tent_request_t`. Add `tent_request_v2_t` and `tent_submit_v2` beside the
  existing TENT C API instead of extending either legacy struct.
- Keep the Transfer Engine change to a thin field-conversion boundary. All
  ABI selection, enums, validation, CString ownership, error mapping, and
  compatibility behavior live in `transfer-engine-ffi`.
- Add an owning `TentEngine` Rust wrapper for the repository's existing
  `tent_*` lifecycle. Priority and transport-only requests continue through
  legacy `tent_submit`; policy, deadline, or intent requests use v2.
- Link TENT explicitly through an opt-in `link-tent-native` feature rather
  than assuming `libtransfer_engine` re-exports symbols from `libtent_shared`.
- Reject interior NULs before any native configuration or submission call.
  Preserve policy-name storage until the synchronous native submission has
  copied it into the existing C++ `Request`.
- Expose best-effort task cancellation and metrics status. A zero bound port
  is returned as `None`, distinguishing log-only/unavailable HTTP metrics from
  a successfully listening endpoint.
- Add Python `TransferEngine`, `TransferRequest`, intent/priority enums,
  keyword-only request controls, cancellation, task status, configuration
  overrides, and metrics status. Python contains no native `unsafe` calls.
