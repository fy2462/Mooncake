# Migration Log 2026-07-21-001

Status: Completed

Baseline: `110bfa47aabc713ef1cdf`

## Client OffsetAllocator FIFO eviction

### Upstream

- `63bcc646` adds quota-aware FIFO eviction to the client SSD
  OffsetAllocator backend.
- `3fa5ccd4` restores prepared victims when publishing their removal to the
  master fails.

### Rust migration

- Add a client-side `OffsetAllocatorStorageBackend` with a persisted JSON
  index, a bounded data file, reusable/coalescing extents, and FIFO ordering.
- Dispatch file-per-key and OffsetAllocator storage through an internal Rust
  enum instead of reproducing the C++ backend class hierarchy.
- Read the supported eviction policy, byte/key limits, ratios, and per-offload
  cap from the upstream environment variables.
- Apply byte and key-count high/low watermarks, including the upstream
  fallback victim batch after the key high watermark has already been
  exceeded.
- Prepare victims as an immutable selection before notifying master. Victims
  remain readable and live usage is unchanged while notification is pending;
  a failed notification simply drops the selection. After a successful
  notification, commit removes the selected generations, and they remain
  evicted even if the new disk write fails.
- Reuse freed extents only after eviction publication succeeds.
- Route offload, promotion, P2P reads, remove-all cleanup, disk watermark
  eviction, and background capacity reporting through either backend.

## Persistence compatibility

- Existing indexes without `next_offset`, `fifo_seq`, or `next_fifo_seq` are
  normalized during initialization.
- The append cursor is recovered from both live entry ends and the data-file
  length, preventing a restart from overwriting existing objects.
- Missing FIFO order is rebuilt deterministically by offset and persisted.
- A restart regression verifies that committed victims remain absent and live
  objects remain readable.

## Rust design notes

- Behavior and transaction semantics were migrated without copying C++ output
  parameters or class-shaped dispatch.
- Extent allocation returns `(offset, next_offset)` by value.
- `PendingOffsetEviction` is an owned transaction token: rollback consumes an
  uncommitted selection without mutating live state, while commit validates
  the selected entry generations and finalizes their removal.
- `MOONCAKE_OFFSET_MAX_CAPACITY_NODES` tunes the native C++ allocator's
  internal node pool. Rust uses a `BTreeMap` extent index, so this
  implementation-only knob has no meaningful Rust equivalent and is not
  exposed as a no-op setting.
