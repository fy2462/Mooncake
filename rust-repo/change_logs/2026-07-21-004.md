# Refactor Log 2026-07-21-004

Status: Completed

## Scope

Replace repeated positional client-bootstrap arguments with a private,
named-field Rust configuration value. This is a behavior-preserving refactor.

## Rust refactor

- Add a module-private `ClientConfig` borrowed view for bootstrap inputs.
- Keep every existing `MooncakeClient::create*` signature unchanged as a
  compatibility facade.
- Pass one configuration value through master selection and connected-client
  construction instead of repeating eight to ten positional arguments.
- Restrict configuration fields to the containing client module.
- Do not expose a public builder until defaults and validation can be specified
  without adding new behavior.

## Compatibility

- Master candidates are still attempted in their original order.
- Validation order and error values are unchanged.
- `create_for_tenant` still applies its tenant after bootstrap, while
  `create_with_master_candidates_for_tenant` still carries its tenant through
  bootstrap. This intentionally preserves the pre-refactor distinction.
- Environment lookup, transport setup, memory registration, segment mounting,
  and constructed client state are unchanged.
- No public Rust or Python call shape changed.
