# Docker Soft-RoCE multi-node validation

The ARM64 validation used the labeled `shared-rdma-device` topology because
the host kernel exposes RDMA namespaces in `netns shared` mode. The initial
per-container `rxe-a`/`rxe-b` topology reached ACTIVE and exchanged QP data,
but its first Write completion failed; it is retained as a negative result.

The fallback verbs gate passed 10 64-KiB RDMA Writes at an observed average of
7.40 Gbit/s. Transfer Engine then passed explicit RDMA Write and Read stages
and logged `RDMA compare: OK`.

Rust Master plus two Rust Store segments passed 4-KiB and 12-MiB put/get,
three repeated reads, hash validation, and forced removal. Both objects had
complete RDMA replicas on segments `10.90.0.1:12401` and
`10.90.0.1:12402`. The Python extension links Transfer Engine and TENT and
does not link the C++ `libmooncake_store.so`.

Open-RDMA mock was run separately at revision
`c62111ce56ec27c3a3fa4fc7b4d82fecf394a83c`. It failed to compile in the
pre-existing dirty checkout; the checkout status was identical before and
after. This mock result is not used as cross-node data-plane evidence.
