# Migration Log 2026-07-21-015

## Parallel HugeTLB population before registration

### Upstream

- `70ba3158` defers HugeTLB population and touches huge pages in parallel
  immediately before RDMA memory registration.
- Population is bounded by available hardware parallelism and the number of
  pages in the mapping.

### Rust migration

- Keep HugeTLB mmap lazy and retain the existing regular-memory fallback when
  the mmap cannot be created.
- Record the actual huge-page size with the owned mapping and partition all
  pages into bounded, non-overlapping worker ranges.
- Populate only RDMA HugeTLB mappings, immediately before both scratch-buffer
  and segment-buffer registration. TCP and regular `Vec` allocations retain
  their existing behavior.
- Centralize mmap, volatile page touching, slice construction, teardown, and
  Transfer Engine memory registration in the crate-level `memory_ffi` adapter.
  The `client/` implementation receives only safe owned-buffer operations and
  introduces no unsafe code.
- The current Rust allocation path has no per-region NUMA binding metadata;
  no NUMA-specific population path is enabled or inferred.
