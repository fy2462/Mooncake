## Accelerator-aware client copy paths

### Upstream

- `ea5fd923` prevents local Store copies from treating accelerator virtual
  addresses as host memory.
- Device-source writes stage through registered host memory; full and ranged
  reads into device destinations stage on host before the final device copy.

### Rust migration

- Add an isolated `accelerator_memory_c` adapter for pointer classification
  and synchronous D2H/H2D copies. The existing `transfer_engine_c` API and
  implementation remain unchanged.
- Bind the adapter in `transfer-engine-ffi` and keep all native calls inside
  the FFI/`data_plane_ffi` boundary.
- Add a mockable accelerator backend and capability-style foreign-memory
  region; client business modules introduce no new unsafe code.
- Preserve direct TE submission for host pointers. Stage device-source writes,
  full device-destination reads, local-disk reads, and packed multi-range
  device reads through the registered client buffer.
- Accept integer addresses such as `tensor.data_ptr()` in Python pointer APIs,
  while preserving existing Python buffer-protocol calls.
